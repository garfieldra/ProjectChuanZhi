# 寻声首页设计与衔接

## 页面与视觉

首页 `/` 以简短产品介绍、唱片视觉和中下部的会话输入框构成；`/explore` 是原有音乐探索工作台。导航中的“进入探索”可继续最近对话；首页提交的新想法开启独立会话，跳转后的 `conversation` 参数只包含会话 ID，不包含用户输入。

视觉采用音乐杂志／唱片店方向：暖白 `#f8f7f4`、墨色 `#242320`、砖红 `#a64b3c`、灰褐细线；宋体标题与简洁系统无衬线控件。开放版式、7px 输入框圆角、3px 按钮圆角，无界面渐变或投影。概念中的唱片摄影作为独立透明 WebP 素材使用，其封套上的 SOUNDSEEK 属于画面内容。

页面顺序：品牌与双链接导航 → 两行大标题与产品介绍／唱片画面 → 会话输入与开始探索按钮 → 两个填入话题的快捷入口 → 三条简短能力说明 → 署名。首屏不新增角标、统计数字、推荐榜单或功能卡片网格。

参考画面布局：1448×1086；页边距约40px、内容最大宽1320px、主输入宽1040px。标题约84px，正文17–21px，控件14–19px。小屏将唱片移至介绍下方，输入保持可见且不横向溢出。

## 真实衔接

1. 提交前先读取 auth/session，建立访客与 CSRF Cookie。
2. 创建会话，将输入作为首条消息发送至既有 messages 接口。
3. API 接受消息后，进入 `/explore?conversation=...`；对话页选择这段会话，并沿用既有 AgentRun 事件恢复。
4. 消息提交失败时保留输入、已创建的会话 ID 和相同 Idempotency-Key。服务端接受消息后界面加载失败再重试也不会重复发送。

输入草稿保存在当前标签页 SessionStorage，禁止将消息放入 URL。输入为空或连接中不重复提交；Enter 发送，Shift+Enter 换行，中文输入法确认不发送。网络超时和服务不可用显示可读错误，并允许重试。

View Transition API 可用时，在首页与工作台之间对品牌和输入区域做约360ms的共享元素过渡；不可用时使用约360ms的轻微位移与淡出淡入兼容过渡。遵守 prefers-reduced-motion。工作台按需加载，并在输入框获得焦点时预加载。

## 验证边界

浏览器的接口夹具用于核验首页→会话、重试、消息只提交一次、刷新恢复和响应式布局；真实音乐推荐与第三方模型质量不由界面夹具证明。
