# 账号系统完善方案

状态：精简范围已实现；验证范围见 [账号验证记录](./account-validation.md)；2026-11-11。开发分支 `codex/account-system-improvements`，基线为 `main@8811b63`。本文按当前项目规模定义一次可完成的账号功能闭环，不拆分阶段交付。

本方案补充 [首版账号身份与访客资产归并规格](../Specs/03-技术架构/22-账号身份认证与访客资产归并规格.md)。本文与原规格冲突时，以本文为准。邮件采用 SMTP；2026-11-11 用户确认仅实现停用和清理范围预览，不开发物理删除命令。

## 1. 范围与默认决策

保留访客直接使用、邮箱密码登录、GitHub 登录、昵称修改和登录后资产归并。继续采用 Java/Spring Security、MySQL、Redis Session，不新增身份服务或 JWT。

| 本次完善 | 目标 |
| --- | --- |
| 邮箱验证 | 新邮箱注册先验证归属；旧账号可登录后补验证 |
| 密码管理 | 支持忘记密码、修改密码，保证恢复后旧会话失效 |
| 邮箱修改 | 登录后再认证、验证新邮箱、切换登录地址并通知旧地址 |
| 会话失效 | 支持当前退出与退出全部设备；停用账户和旧会话不能继续访问 |
| 维护者授权 | 按账户 UUID 显式配置，取消邮箱自动授权 |
| 登录防护 | 独立 IP、账号与组合限流，登录失败统一提示 |
| 数据归属 | 保留访客归并、跨设备同步和现有业务所有权检查 |
| 运维与测试 | 受控账号停用/注销、安全事件记录、迁移与隔离验收 |

本次不加入 MFA、设备详情列表、自动数据导出、公开管理后台、GitHub 自助绑定解绑、短信或微信/QQ 登录。GitHub 与邮箱账户按现有独立身份使用，不根据相同邮箱自动合并。注销先提供受控运维流程，不增加自助注销与 7 天撤销工作台；这些都不作为本次交付验收要求。

邮件使用可配置 SMTP，本地用隔离收件箱。生产 SMTP、发信地址和站点域名在部署时配置，不购买或绑定特定供应商。未配置邮件时访客和已有登录仍可用，新注册/找回/改邮箱明确提示暂不可用，不假报发送成功。

## 2. 身份与维护权限

账户 UUID 是稳定身份，Session Principal 改为 `user_account.id`；邮箱只作为登录标识和联系地址。业务数据继续通过账户的 `primary_guest_session_id` 归属，客户端不能指定 owner。

维护者使用服务端 `KNOWLEDGE_MAINTAINER_IDS` 配置已存在账户的 UUID，并同时检查账户 ACTIVE、真实邮箱已验证。注册、验证邮箱或首次 GitHub 登录都不会自动授予维护权限。旧 `KNOWLEDGE_MAINTAINERS` 停止参与授权，只用于运维核对旧名单，不自动映射到新授权。

维护者账号由运维核实后显式加入配置；配置变更重启 Java 后生效，同一维护版本部署到全部实例。已停用账户即使仍在名单中也被拒绝。暂不增加通用角色表或管理员账户管理页面；运维操作由主机权限保护的 CLI 调用同一业务服务并记录审计，不能直接修改数据库绕过验证。

新 GitHub 用户继续按 Provider Subject 识别，内部 `github-{subject}@users.soundseek.local` 不能作为真实邮箱或找回地址。GitHub 用户可在登录并完成近期 GitHub 再认证后添加已验证联系邮箱，用于安全通知及维护准入；本次不为 GitHub-only 用户新增密码身份，其登录恢复仍由 GitHub 完成。

## 3. 用户流程

### 3.1 邮箱注册与验证

1. 提交邮箱、密码、昵称，只创建 30 分钟有效的注册申请，密码只保留摘要。
2. 发送确认邮件；GET 链接只打开页面，不执行注册，用户显式 POST 确认。
3. 同浏览器确认须校验申请浏览器绑定；跨设备确认须重新输入申请密码，防止仅点击他人发起的邮件就接收他人预设密码。
4. 在同一事务中检查邮箱唯一性、创建账户与密码身份、消费申请并关联当前用户确认的访客空间；成功后轮换 Session ID 和 CSRF Token。

注册前仍能使用访客功能。未验证申请不永久占用邮箱，不同申请不能互相覆盖密码，重复确认只能成功一次。跨设备确认不自动归并原申请设备的访客资料。

公开注册/找回接口使用统一受理提示，不暴露邮箱是否已有账户；邮件按真实状态提供对应引导。地址仍按现有 trim、大小写规范化处理，不擅自合并点号或加号后缀地址。

### 3.2 已有账户补验证

迁移时真实旧邮箱标为未验证，保留正常登录和音乐使用能力。补验证需已登录并再次证明当前密码或完成 GitHub 再认证；确认后标记验证时间。未验证账户不能获得维护权限或自助邮件找回。

旧邮箱无法登录且未验证时，提供明确的运维求助说明，由受控流程核实后处理，不开放只凭历史邮箱即可重置的接口。处理须撤销会话、复核关联身份和维护资格，记录理由；不能仅证明当前邮箱归属就自动把旧账户全部资料交给申请者。

### 3.3 找回与修改密码

已验证的密码账户可申请 20 分钟有效的恢复链接。确认时原子消费令牌、更新密码、递增 `auth_version`，撤销全部会话和旧恢复挑战；成功后重新登录，不自动建立新会话。

已登录修改密码要求当前密码；成功后递增 auth_version、使其他设备失效，并为当前设备重新签发会话。邮箱验证不能代替改密的当前密码证明。

继续使用 BCrypt(12)，新设密码至少 10 个字符、最多 72 个 UTF-8 字节，前后端规则一致，不静默截断；历史密码摘要保持可验证。允许密码管理器和粘贴，密码不进入日志、前端存储、SSE 或 Agent 上下文。

### 3.4 修改邮箱

密码用户先验证当前密码；GitHub 用户通过绑定当前账户与会话的 GitHub 再认证。证明成功后 10 分钟内可发起变更。

新邮箱确认挑战 30 分钟有效，绑定账户与 auth_version；确认前旧邮箱有效，确认后事务检查唯一性并更新联系邮箱和密码登录标识，递增 auth_version、使其他设备和旧挑战失效，当前设备重新签发会话。向新旧已验证地址发送通知，旧地址不能继续用于找回。

GitHub-only 用户添加或修改联系邮箱不创建密码身份，也不和相同邮箱的其他账号自动绑定。邮箱冲突时保留原状态，不能静默迁移资产。

### 3.5 登录、会话与停用

保留 Redis Session、CSRF、登录轮换 Session ID、HttpOnly/SameSite Cookie；生产 Secure Cookie 必须开启。会话默认闲置 30 天、绝对 90 天，可配置。

每个已登录请求统一核对账户 ACTIVE 和 auth_version，不把邮箱或旧 Session 中的状态当权威。密码验证或 GitHub 授权成功后，在签发会话前再核对状态/版本，防止并发停用或改密后仍产生有效旧凭据会话。

当前退出只销毁当前 Session；退出全部设备先递增数据库 auth_version，再尽力删除 Redis Session。Redis 删除失败也不能让旧版本继续访问。退出或身份失效后建立新访客空间，不能通过旧访客 Cookie 继续读取账户资产。

SSE 在事件发送前及最长 15 秒心跳间隔内复核会话，失效即关闭。普通退出不取消 ACTIVE 账户已经提交的后台任务，重新登录后可读结果；账号停用/注销则取消运行并拒绝旧租约结果。Worker 回调校验账户状态、资产归属与运行版本，不依赖浏览器 Session 是否仍存在。

客户端同步其他标签页的登录状态并清除旧用户私有视图、会话和收藏缓存；旧网络响应不能覆盖新身份。身份检查依赖不可用时返回明确错误，不能保留 ROLE_USER 再默默退到访客空间。

### 3.6 访客资产归并

注册确认或完整登录成功后才执行现有事务归并，保留歌曲收藏去重、来源卡片、对话、赛事和偏好等归属；固定顺序锁定来源与目标，重复提交幂等，失败不报告登录成功。归并完成撤销原访客令牌。

在途访客 Agent Run 需先取消并提升运行版本，拒绝原 owner/旧租约回调，再迁移记录；保留原消息和已完成卡片，明确提示未完成请求重新发送。不能只改 owner 后让旧 Worker 继续写回，也不能无提示丢失待发消息。

### 3.7 受控停用与清理预览

本次只实现受主机权限保护的 CLI：preview 展示账户 UUID、状态和资产数量，disable 在明确 UUID、再次确认 UUID 与理由后停用账户。停用递增 auth_version、取消在途任务、失效会话和挑战，并写入审计；保留现有账户资料和业务资产。

本次不开发、不执行物理删除命令，不提供自助注销；界面明确说明当前支持停用，数据删除需另行确认处理范围和授权。预览不可误报为已清除，恢复备份及保留周期也不在本次命令中自动处理。

## 4. 最小数据与接口变化

扩展 `user_account` 的真实联系邮箱（可空）、验证时间和 auth_version；保留 UUID、主资产空间和历史密码/GitHub Subject。旧 `email_normalized` 的唯一/非空约束及内部占位值须在迁移中明确改造，不能直接把占位地址当真实邮箱；登录入口改查有效密码身份与联系邮箱。

仅新增注册申请、一次性挑战、邮件投递任务与安全事件数据，不引入角色、设备、MFA、恢复码或导出任务表。停用审计保存在受控运维任务记录中。

| 接口（以 `/api/v1` 为前缀） | 行为 |
| --- | --- |
| `POST /auth/register` | 返回 202，创建申请，不立即登录 |
| `POST /auth/registration/confirm` | 验证并完成注册 |
| `POST /auth/email-verification/request`、`POST /auth/email-verification/confirm` | 旧账户补验证 |
| `POST /auth/password-reset/request`、`POST /auth/password-reset/confirm` | 忘记密码 |
| `POST /me/password` | 当前密码验证后改密 |
| `POST /auth/reauth` | 密码再认证；GitHub-only 返回受控的再授权入口 |
| `POST /me/email-change/request`、`POST /me/email-change/confirm` | 新邮箱添加/修改与验证 |
| `POST /auth/logout-all` | 再认证后退出全部设备 |
| 现有 login/logout/session/profile 与 GitHub 回调 | 保留并接入 UUID Principal、状态与版本校验 |

`session` 兼容扩展 userId、emailVerified、loginMethods；前端不依赖邮箱判断身份或授权。再认证绑定当前账户、Session、用途和版本，10 分钟到期；不向客户端发放可转用的通用再认证 bearer token。GitHub OAuth state 区分 LOGIN/REAUTH 并验证发起会话，只允许本站回跳；本次无 LINK 流程。 GitHub 再认证前保存绑定账户、有效 10 分钟的非敏感待办，回调后的专用页面展示原操作及邮箱，由用户再次确认执行；不自动发信或退出。改邮箱确认令牌仅通过服务端 Session 加密保留，并只允许回到本站 CHANGE_EMAIL 确认页；不写入浏览器存储。

全部变更请求校验 CSRF，包括注册/找回/确认。请求校验用 DTO，挑战错误统一处理，稳定错误码区分认证失败、需要再认证、频率限制和服务暂不可用。发信和关键变更支持幂等键，不能因用户重试重复创建账户或投递大量邮件。

## 5. 邮件与防滥用

邮件令牌采用至少 256 bit 的密码学随机值，数据库只存摘要，区分用途、账户/申请、版本和到期；事务锁定后原子消费。注册/补验证/改邮箱 30 分钟、找回 20 分钟、OAuth 事务 10 分钟，重试不续期。确认链接只打开页面，令牌用 fragment 临时传递并立即清理，不进入日志、埋点、localStorage 或第三方资源请求。

使用现有事务 Outbox 思路，独立邮件任务由 Java 定时消费者发送，无需新增 Python 服务或 RabbitMQ 邮件专用进程。待发链接参数加密，密钥由环境注入；投递完成/期满后删除密文，日志只记事件与脱敏错误。发送前检查挑战仍有效；SMTP 响应不明时允许同一邮件重投，但不能重新生成令牌或越过发信额度。

限流独立统计账号、IP 与组合，Redis 原子写入计数和期限。初始默认：组合失败 10 次/15 分钟、账号失败 20 次/15 分钟、IP 登录 60 次/分钟；发信每邮箱每分钟 1 封、每小时 5 封，IP 每小时 20 封，并设置全局发信上限。注册/找回确认不使用固定字符串作为账号限流键：来源 IP 每分钟 60 次，来源与用途组合每 15 分钟 10 次；有效挑战另按挑战 ID 与用途每 15 分钟 20 次，无效令牌只计来源额度，不创建任意令牌桶。确认额度复用对应登录限流配置。参数可配置；频率达到阈值返回 429，窗口期满可重试，不永久锁号。只信任部署指定代理提供的来源信息，具体网络和地址见账号维护说明。Redis 不可用时认证变更/发信明确失败，不无限放行。

安全事件记录登录、验证、改密、邮箱变更、全端退出、运维停用/注销和授权配置变更。记录对象 UUID、结果、关联 ID 与时间；不记录密码、Cookie、完整令牌和整封邮件。

## 6. 迁移与配置

1. 从当前 main 检查最新 Flyway 序号，目前为 V25；只追加迁移，不改旧迁移或自动 repair。
2. 保留账户 UUID、密码摘要、GitHub Subject、主资产空间和全部业务数据。旧真实邮箱迁为未验证，GitHub 占位邮箱不作为真实联系地址；重复/异常记录预检失败后报告，不自动合并账户。
3. 清点所有 Principal 使用点并改为 UUID，升级 Session 命名空间使旧会话失效，部署后需重新登录。新旧认证协议不混跑。
4. 旧邮箱白名单停止授权，维护者重新核实邮箱并按 UUID 配置；默认空名单，升级安排维护暂停窗口。回退版本不得重新启用旧邮箱授权漏洞。
5. 配置 SMTP、发信地址、固定 AUTH_PUBLIC_BASE_URL、邮件参数加密密钥、可信代理及生产 Secure Cookie。邮件 URL 不信任请求 Host，密钥不进入仓库、前端或 Agent 配置。
6. 用独立 MySQL/Redis 和隔离收件箱验证升级与完整流程；生产真实邮件联通另行记录。本次方案不直接迁移或清理用户业务数据库。

依赖和缓存继续遵循 E 盘偏好。方案不会引入新的商业身份服务或强制购买发信套餐。

## 7. 验收标准

| 范围 | 必须验证 |
| --- | --- |
| 注册 | 未验证不创建正式账户；重复、期满和跨浏览器确认安全；邮件 GET 无副作用 |
| 维护权限 | 抢注白名单邮箱无权限；只允许已验证、ACTIVE 且明确配置的 UUID |
| 密码 | 找回、改密、长度边界、令牌一次消费、改密与登录并发、旧会话失效 |
| 邮箱 | 补验证、改邮箱、唯一性冲突、旧地址失效、GitHub-only 不误建密码身份 |
| OAuth | 原有登录正常；停用账户拒绝；LOGIN/REAUTH state、会话绑定与回跳校验 |
| 会话 | 当前/全部退出、跨标签状态、旧响应清理、Redis 清理失败仍拒绝旧版本、SSE 关闭 |
| 资产 | 访客归并幂等、数据不丢失、旧访客令牌无效、在途任务旧回调拒绝、其他用户隔离 |
| 邮件/限流 | 真实隔离收件、重试与到期、脱敏、多维额度、依赖失败无虚假成功 |
| 运维 | 停用立即失效；清理范围只预览、不删除，公共资料与他人数据不受影响 |
| 升级 | 空库及既有账户数据的真实隔离 MySQL 升级；无默认维护者，原业务数据保留 |

Java 单元和 MySQL/Redis 集成测试覆盖事务、权限和失效；Web 测试与隔离浏览器验收覆盖注册、邮件确认、找回/改密、退出及访客归并。GitHub 用可控 Provider 验证回调，真实生产联通在配置后记录。记录实际测试结果，不沿用既有 RAG 数量，不要求音乐语料评测。
