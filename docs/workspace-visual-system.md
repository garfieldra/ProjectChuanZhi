# 工作区视觉系统 Spec

日期：2026-11-03。状态：已实施并通过本轮验收。分支：feature/frontend-improvements。

## 目标与边界

以暖白、砖红、音乐杂志风格提升正式产品的视觉一致性。保留首页首屏的构图、文案与唱片素材；不新增首页深色分区。保留三栏信息架构、所有现有接口、Apple 试听、统一 Agent 与业务行为。不增加新运行时依赖。

工作台头像及账户配置始终位于左下角，仍为贴靠头像的非模态逐级菜单；不引入遮罩、页面跳转或滚动锁。首页账户菜单仅继承共享控件规范。

## 设计契约

- 共享语义 token：画布 #f8f7f4、侧栏 #efeee9、表面 #fffefb、墨色 #242320、辅助文字 #6b675f、细线 #dedbd4、砖红 #a64b3c、选中背景 #f4e8e3；深色播放器 #252522、浅色文字 #faf8f3。
- 系统无衬线负责正文/导航/表单；宋体仅负责品牌与作品标题。正文 16px/1.85，控件 14px，辅助文字 12–14px；信息文字须可读，保留键盘焦点提示。英文/时间数字采用稳定的数字宽度。
- 间距尺度 4/8/12/16/24/32/48px；小控件 8px、业务卡片与菜单 16px；输入框沿用桌面24/手机20px；用户气泡沿用20/18px。开放排版优先，减少嵌套边框。
- 桌面保留左导航/中对话/右补充三栏；正文与输入框共享对齐线和最大宽度。中等窗口沿用辅助栏折叠策略，手机沿用抽屉导航，中央内容不横向溢出。
- 当前会话使用淡砖红选中态。助手正文采用开放排版与明确段落间距；用户消息保持圆角。来源链接与反馈按钮有一致焦点和悬停样式。
- 推荐行统一封面裁切/缺图占位/长标题换行规则；播放选中态呼应砖红。播放器为局部炭黑表面，歌名、作者、时长、进度与按钮有对比清晰的专用颜色。

## 动效契约

控件反馈120–160ms；账户菜单180ms淡入上移，子菜单约180ms向前/向后过渡。新推荐区块约240ms淡入上移。历史消息恢复不重复入场；流式正文不逐字动画，不对持续变化的高度做无限过渡。禁止用 CSS transition:all。

播放器复用真实音频与现有频谱/旋转实现，不添加模拟频谱。系统或用户减少动态效果时关闭新增位移动画。菜单不因动效丢失焦点、草稿或滚动位置。

## 实施顺序

1. 写入本 Spec；生成桌面完整工作区参考（包含推荐/播放器），据其构图实现现有界面。
2. 引入共享 token 和工作区视觉样式；明确懒加载的加载顺序，避免首页被工作区样式污染。
3. 修改菜单的层级切换动效与新卡入场标记；维持现有逻辑。
4. 构建、现有测试、浏览器桌面/手机交互验收；修复后复验。将结果记录在本文。

## 验收

- 首页首屏无新增/删除文案、无重构布局；直接进入 /explore 和从首页进入的工作区样式一致。
- 1440×900、1280×720、390×844、320×740 下无横向溢出/重叠；左下角头像不遮挡发送与记忆按钮。
- 使用接口夹具检查长回答、推荐、缺封面、深色播放器、账户菜单/返回/Escape、空态/错误/运行状态；夹具不代表真实模型和全部第三方歌曲联调。
- 菜单仍无 backdrop/scroll lock；键盘可操作；草稿及URL不随设置切换变化。
- 真实播放逻辑和减少动态效果继续由现有测试覆盖；检查渲染中的文字/背景对比、控件焦点、手机断行。
- npm test、npm run build、git diff --check 通过。
