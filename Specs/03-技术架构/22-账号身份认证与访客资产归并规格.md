# 账号、身份认证与访客资产归并规格

## 1. 目标与边界

IndieSoundQuest 继续允许访客直接开始音乐对话。账号用于跨设备恢复对话、赛事、报告与长期偏好，不得把登录变成首次使用的门槛。

首版支持邮箱密码与 GitHub OAuth2。微信、QQ 等需要平台审核或主体资质的登录方式不进入首版。Java 服务是唯一身份与授权中心；Python Agent 不接收密码、OAuth Token、Session ID 或其他认证凭据。

## 2. 身份模型

- `user_account`：用户主体，保存展示名、规范化邮箱、状态和主资产空间。
- `auth_identity`：登录身份。`PASSWORD` 保存单向密码摘要；`GITHUB` 保存稳定的 Provider Subject。一个用户可以绑定多个身份。
- `guest_session`：继续作为现有业务数据的资产空间。每个账户拥有一个主 Guest Session，以兼容现有赛事、对话和 Agent Run 所有权模型。
- 相同邮箱不得自动绑定第三方身份；OAuth 身份冲突时必须由已登录用户显式绑定。首版 GitHub 首次登录仅在 Provider Subject 未存在时创建新账户。

## 3. 会话与浏览器安全

- 使用 Spring Security 和服务端 `HttpSession`，Session 由 Redis 承载。
- 浏览器只保存 `HttpOnly`、`Secure`（生产环境）、`SameSite=Lax` 的会话 Cookie。
- 不在 `localStorage` 保存 JWT、密码或第三方 Token。
- 登录成功后轮换 Session ID；退出时服务端 Session 立即失效。
- 访客空间升级为账户资产后，原访客令牌必须在同一事务内撤销；退出后不得凭旧访客 Cookie 继续读取账户资产。
- 修改类请求启用 CSRF 防护；前端通过 CSRF Cookie/Header 双提交。
- 密码使用 BCrypt 或 Argon2id 单向摘要；日志、SSE、Agent 上下文不得包含认证凭据。

## 4. 访客升级与资产归并

注册时，当前 Guest Session 直接成为账户主资产空间，因此无需复制数据。

已有账户在新设备登录时，系统在数据库事务内把当前访客空间归并到该账户的主资产空间。归并范围包括：

- 对话、消息与中期记忆；
- 赛事、投票和报告；
- Agent Run、事件、干预与待发送消息；
- 偏好事件、长期偏好记忆与偏好档案。

归并必须锁定来源和目标身份，支持幂等重试。唯一键冲突时保留目标空间的稳定记录；可从赛事重新推导的偏好档案允许失效后重建。归并完成前不得向客户端报告登录成功。

## 5. API

- `GET /api/v1/auth/session`：当前账户与 CSRF 初始化状态。
- `POST /api/v1/auth/register`：邮箱、密码、展示名注册并登录。
- `POST /api/v1/auth/login`：邮箱密码登录并归并当前访客资产。
- `POST /api/v1/auth/logout`：退出并回到新的访客空间。
- `GET /oauth2/authorization/github`：发起 GitHub 登录。
- `GET /login/oauth2/code/github`：Spring Security 回调端点。

认证失败对外使用统一文案，不暴露邮箱是否存在。登录与注册按来源地址和规范化邮箱组合实施独立限流；OAuth 依赖 Provider 的授权状态校验，并保留接入网关级限流的扩展点。

## 6. 前端体验

- 左侧栏底部展示克制的账户入口；未登录显示“登录以同步”，登录后显示头像、昵称与退出入口。
- 登录采用页面内模态层，不打断当前对话；注册或登录完成后原访客内容仍停留在当前页面。
- GitHub 登录使用整页跳转，回到首页后重新加载账户和资产。
- 认证错误使用中文可恢复提示，不展示堆栈、状态码或内部实现语言。

## 7. 验收标准

1. 未登录用户仍可完成全部核心音乐探索流程。
2. 注册后当前访客对话不丢失。
3. 已有账户从新访客空间登录后，两边资产都出现在账户主空间。
4. 用户无法读取、修改或订阅其他账户的对话、赛事、报告和 Agent Run。
5. 密码摘要、Session、OAuth Secret 不进入日志、前端存储、SSE 或模型上下文。
6. 重复提交登录/归并不会复制资产或破坏唯一约束。
7. GitHub 凭据缺失时邮箱登录和访客模式仍正常可用。
